## Explanation

This PR consists entirely of markdown prompt files, skill definitions, documentation, and a JSON version bump. There is no executable code (no scripts, no compiled binaries, no application logic, no API endpoints, no data processing) in the changed files. The security dimension is not meaningfully applicable to these changes.

That said, the changes were evaluated against all requested security considerations, and no issues were found:

### Prompt Injection Risks

The skill definitions in `shared/skills/self-review/SKILL.md` and `shared/skills/parallel-review/SKILL.md` are prompt templates consumed by Claude Code's own skill system. They instruct the AI agent on review behavior, scoring dimensions, and output formatting. These prompts do not accept untrusted user input that could be injected into the prompt context in a way that would alter behavior. The PR context (diff, commit messages, PR body) that feeds into reviews is fetched via MCP tools at runtime, not interpolated into the skill markdown. The prompt template files (`.github/prompts/claude-code-review.md` and `plugins/scm-utils/skills/code-review/references/prompt-template.md`) use `${REPO}`, `${PR_NUMBER}`, and `${JOB_CONTEXT}` via `envsubst`, which are controlled by the CI workflow environment, not by PR authors.

### CDATA Fix Effectiveness

The CDATA fix adds explicit `CRITICAL: NEVER wrap any part of your review output in <![CDATA[...]]> tags` instructions in three locations:
- `.github/prompts/claude-code-review.md` (line 286)
- `plugins/scm-utils/skills/code-review/references/prompt-template.md` (line 206)
- `shared/skills/self-review/SKILL.md` (line 105)

This is a prompt-level mitigation — it instructs the model to avoid CDATA output. It does not programmatically strip CDATA from output before posting. The analysis document (`docs/review-system-analysis.md`, section 5.3) correctly identifies this gap and recommends an output validation gate as a future improvement. The prompt-level fix is a reasonable first step but not a guarantee.

### Review Output Format Abuse

The review output is posted via GitHub's review API by an authenticated GitHub App. The output format uses standard GitHub-flavored markdown (details/summary blocks, shields.io badges, footnotes). Since the review bot reads PR content but the output is generated by the model (not echoed user input), there is no direct injection vector from PR content into review output that would execute code or alter permissions. The shields.io badge URLs are constructed from scores and labels, not from arbitrary user input.

### Secrets and Credentials

No secrets, API keys, tokens, or credentials are exposed in any changed file. The `github-auth` shared skill (not part of this PR's changes) contains only placeholder tokens (`ghp_xxxxxxxxxxxx`, `ghs_xxxxxxxxxxxx`). The `plugin.json` contains an author email (`nsheaps@gmail.com`) which is already public on the author's GitHub profile. Required secrets (`REVIEW_GITHUB_APP_ID`, `REVIEW_GITHUB_APP_PRIVATE_KEY`, etc.) are referenced by name only in the code-review SKILL.md documentation, not by value.
