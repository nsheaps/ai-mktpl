The doc at `ai-mktpl/.claude/rules/ongoing-issues.md` is a list of issues that are ongoing between sessions. This list is continually updated by other sessions, and MUST be updated by sessions that detect new or repeated issues. This is critical for autononmy across ephemeral sessions. The list may be added to and removed from quite often, and any merges with upstream branches should ensure that no upstream changes are lost. If the list dwindles to empty, the file should remain and contain only this warning and "<no current issues exist>".
All ongoing issues MUST be tracked in a github issue and cross linked here and on every code change made. See @./github-issues-task-management.md.

The current issues are:

- Repeated permissions issues since claude-code cli update where changes in .claude require permissions prompts https://github.com/nsheaps/ai-mktpl/issues/261
- Plugins set up in project settings.json are not installed and made available on initial session launch, but are later available. Root cause identified 2026-08-12: on a fresh cloud session, plugin `Setup{init}`/`SessionStart` lifecycle hooks never fire because those events already passed before the plugins existed on disk. `ai-mktpl` (`.claude/hooks/session-start/01-install-plugins.sh`) and `.ai-agent-jack` (`bin/hooks/session-start-install-plugins.sh`) have a workaround that manually installs enabled plugins and re-fires their lifecycle hooks; `agents`, `claude-utils`, `nsheaps`, and `.github` do not yet. Tracked in https://github.com/nsheaps/ai-mktpl/issues/745. Re-confirmed 2026-08-13 in a cloud session: every `shared-lib` invocation logged `event=unknown` (the workaround `eval`s hook commands with no stdin payload), so native SessionStart dispatch still does not fire. Evidence: [docs/research/cloud-session-jack-credential-chain.md](../../docs/research/cloud-session-jack-credential-chain.md) §2.
- Agent egress policy blocks the GitHub App token exchange (`POST /app/installations/{id}/access_tokens`) and bot-user lookup (`/users/<slug>[bot]`), so cloud sessions cannot mint a Jack installation token and cannot author commits as Jack. Commits fall back to `Claude <noreply@anthropic.com>`. https://github.com/nsheaps/ai-mktpl/issues/756 — evidence: [docs/research/cloud-session-jack-credential-chain.md](../../docs/research/cloud-session-jack-credential-chain.md) §3-4.
- `github-app` skips silently when credentials are configured but unreachable, so the session commits under a different identity with no visible warning. https://github.com/nsheaps/ai-mktpl/issues/757 — evidence: [docs/research/cloud-session-jack-credential-chain.md](../../docs/research/cloud-session-jack-credential-chain.md) §3-4.
- `mise` is installed but not activated in the agent Bash environment (`CLAUDE_ENV_FILE` unset), so `op`, `op-exec`, and `gh` exist under `/root/.local/share/mise/installs/` but are absent from `PATH`. Hooks relying on bare `op` on `PATH` see it as missing. https://github.com/nsheaps/ai-mktpl/issues/758 — evidence: [docs/research/cloud-session-jack-credential-chain.md](../../docs/research/cloud-session-jack-credential-chain.md) §2.
- `github:`-backend mise tools cannot resolve in cloud sessions (the GitHub releases API is blocked), so the `op-exec` pin in `mise.toml` is not honoured and a stale image copy is used instead. https://github.com/nsheaps/ai-mktpl/issues/759 — evidence: [docs/research/cloud-session-jack-credential-chain.md](../../docs/research/cloud-session-jack-credential-chain.md) §2.
