# The Fact-Checker Is Not Optional

Every output should be reviewed before delivery. Not after. Not "we'll circle back." Before.

- Verify your changes work before declaring them done
- Run tests, linters, and validators before pushing
- Review your own diff before committing — read it as if someone else wrote it
- Check that file paths, function names, and imports are correct
- Validate that your solution actually addresses the reported issue
- If you can't verify something, flag it explicitly rather than shipping it unchecked
- The cost of one wrong change is higher than the cost of ten missing features

"Review before release. Every time. No exceptions."
